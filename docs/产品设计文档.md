## 1. 产品概述

### 1.1 一句话定位

一款注重隐私、轻量快速的桌面音乐播放器：**本地音乐库管理 + 局域网内多设备音乐共享与串流**，无在线流媒体、无账号、无广告。

### 1.2 要解决的问题

- 主流播放器（QQ 音乐、Spotify 等）以在线内容为中心，对本地音乐库的管理越来越弱。
- 用户音乐文件分散在多台设备：PC、NAS、家庭服务器，缺乏一个轻量的方式在局域网内浏览和播放这些文件。
- 现有方案（foobar2000、MusicBee）功能强但 UI 老旧、配置复杂；NAS 自带应用体验差且被厂商锁定。

### 1.3 目标用户

1. **本地音乐收藏者**：手里有几百 GB～几 TB 的音乐文件（FLAC/MP3/APE），需要好的库管理和播放体验。
2. **NAS / 家庭网络用户**：音乐存在群晖/威联通/自建服务器上，希望在桌面端流畅播放。
3. **多设备家庭**：家里多台电脑都想访问同一份音乐，不想来回拷贝。

### 1.4 核心价值主张

- **纯本地**：所有数据（数据库、缓存、配置）都在本机，不联网上传任何信息。
- **跨源统一**：本地目录、局域网共享目录、NAS 在同一个库里浏览、搜索、排队。
- **轻快**：Tauri 方案安装包 < 15 MB，内存占用 < 150 MB（对比 Electron 方案 150 MB+ 安装包）。
- **开放格式**：MP3 / FLAC / AAC / OGG / WAV / APE(后续) 全支持。

### 1.5 竞品参考

| 产品 | 借鉴点 | 我们的差异 |
| --- | --- | --- |
| foobar2000 | 强大的库管理与格式支持 | UI 现代化、开箱即用、局域网能力 |
| MusicBee | 视图丰富（专辑网格/表格）、自动打标签 | 跨平台、更轻 |
| Dopamine / 耳机 | 简洁美观、专注播放 | 增加局域网源与共享 |
| NAS 自带 Audio Station | 局域网访问 | 不锁定厂商、跨平台、支持任意来源 |

## 2. 需求分析

### 2.1 核心用户故事

- 作为用户，我想**把几个文件夹加入音乐库**，应用自动扫描出所有歌曲并按专辑/艺人/风格组织。
- 作为用户，我想**双击一首歌就播放**，能看到封面、歌词、进度，能拖动进度条。
- 作为用户，我想**创建歌单**、拖拽歌曲排序，并把当前播放队列保存为歌单。
- 作为用户，我想**发现局域网里其他设备上的音乐**（另一台 PC 跑了本应用的"共享模式"，或 NAS 的 WebDAV），像本地文件一样浏览和播放。
- 作为用户，我想**搜索**：输入关键词即时过滤出歌名/艺人/专辑匹配的歌曲。
- 作为用户，我想**最小化到托盘**，用**媒体键**控制播放。

### 3.3 播放引擎的关键决策 ⭐

这是本产品最重要的架构决策，需要在 MVP 阶段就定对方向。

**决策：MVP 采用「WebView `<audio>` + Rust 自定义流协议」，通过 `AudioBackend` trait 预留 Rust 解码引擎的演进路径。**

```
前端 <audio src="music://track/123">
          │
          ▼
Tauri register_asynchronous_uri_scheme_protocol("music")
          │  按 Range 请求流式响应（支持拖动进度条）
          ▼
Rust StreamResolver：
  ├─ track 在本地库  → 直接读文件流
  ├─ track 在 WebDAV → reqwest 代理转发（统一附加凭证、解决跨域）
  ├─ track 在共享源  → 代理转发对方设备的 /stream 接口
  └─ WebView 不支持且未匹配转码规则 → symphonia 解码 → 转出 PCM/WAV 流（P1 兜底）
```

理由：

1. **系统解码器覆盖广**：WebView2（Windows，Chromium 内核）支持 MP3/AAC/FLAC/OGG/WAV/Opus；WKWebView（macOS）支持 MP3/AAC/FLAC/ALAC/WAV。MVP 只需对 macOS 不支持的 OGG 做转码兜底。
2. **输出走系统混音器**：自动获得音量混合、蓝牙耳机、系统音效设置，无需处理音频设备枚举。
3. **Seek 免费**：实现 Range 协议后，`<audio>` 的拖动进度、缓冲管理全部复用浏览器成熟实现。
4. **演进路径清晰**：v2 的 Rust 引擎（rodio + symphonia）实现同一 `AudioBackend` trait，为 gapless、EQ、DSD、独占输出（WASAPI/CoreAudio）留好接口，前端调用方无感知。

**格式兼容矩阵与兜底策略**：

| 格式 | Windows(WebView2) | macOS(WKWebView) | Linux(WebKitGTK) | 策略 |
| --- | --- | --- | --- | --- |
| MP3 | ✅ | ✅ | ✅ | 直连 |
| AAC/M4A | ✅ | ✅ | ✅ | 直连 |
| FLAC | ✅ | ✅ | ✅ | 直连 |
| WAV | ✅ | ✅ | ✅ | 直连 |
| OGG Vorbis/Opus | ✅ | ❌ | ✅ | macOS 转码 WAV 兜底（P1） |
| APE / DSD | ❌ | ❌ | ❌ | v2 Rust 引擎支持 |
| Hi-Res (>48kHz) | ⚠️ 受系统混音器 | ⚠️ | ⚠️ | v2 独占输出解决 |

> Linux WebKitGTK 的编解码器依赖发行版 GStreamer，兼容性最弱，转码兜底对 Linux 是常态而非例外——流协议层必须把"源流"与"实际给前端的流"解耦。

## 4. 数据设计

### 4.1 SQLite 数据模型（ER 概览）

```
sources ──1:N── tracks ──N:1── albums ──N:1── artists
                   │
                   ├──N:1── folders(远程源的目录树, 可选)
                   │
playlist_items ────┘
play_history / favorites
```

核心表 DDL（示意）：

```sql
-- 音乐来源：本地目录 / webdav / lan-share
CREATE TABLE sources (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,            -- 'local' | 'webdav' | 'lan'
  name TEXT NOT NULL,
  base_url TEXT,                 -- 远程源根 URL；本地源为空
  config TEXT,                   -- JSON: 账号/密码(加密)/启用转码等
  enabled INTEGER DEFAULT 1,
  last_scan_at INTEGER
);

CREATE TABLE artists (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  sort_name TEXT
);

CREATE TABLE albums (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  artist_id INTEGER REFERENCES artists(id),
  year INTEGER,
  cover_path TEXT               -- 缓存后的封面文件路径
);

CREATE TABLE tracks (
  id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  path TEXT NOT NULL,            -- 相对 source 的路径（远程为 URL path）
  title TEXT, artist_id INTEGER, album_id INTEGER,
  album_artist TEXT, genre TEXT,
  track_no INTEGER, disc_no INTEGER, year INTEGER,
  duration REAL,                 -- 秒
  bitrate INTEGER, sample_rate INTEGER, channels INTEGER, bit_depth INTEGER,
  has_embedded_cover INTEGER DEFAULT 0,
  has_embedded_lyrics INTEGER DEFAULT 0,
  mtime INTEGER, file_size INTEGER,
  format TEXT,                   -- 'mp3'|'flac'|...
  added_at INTEGER, last_played_at INTEGER, play_count INTEGER DEFAULT 0,
  UNIQUE(source_id, path)
);
CREATE INDEX idx_tracks_album ON tracks(album_id);
CREATE INDEX idx_tracks_artist ON tracks(artist_id);

-- FTS5 全文索引（歌名/艺人/专辑/拼音首字母）
CREATE VIRTUAL TABLE tracks_fts USING fts5(title, artist, album, content='');

CREATE TABLE playlists (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, created_at INTEGER, sort INTEGER
);
CREATE TABLE playlist_items (
  id INTEGER PRIMARY KEY,
  playlist_id INTEGER REFERENCES playlists(id) ON DELETE CASCADE,
  track_id INTEGER REFERENCES tracks(id) ON DELETE CASCADE,
  position INTEGER
);

CREATE TABLE lrc_files (        -- 外挂歌词缓存
  track_id INTEGER PRIMARY KEY REFERENCES tracks(id) ON DELETE CASCADE,
  path TEXT                      -- 本地 .lrc 路径或远程 URL
);
```

远程源（WebDAV/共享）的歌也进 `tracks` 表，`source_id` 区分——这样搜索、歌单对全库生效，播放时通过流协议按 source 路由取流。

### 4.2 扫描算法（增量）

```
scan(source):
  1. walkdir 遍历（远程源为 PROPFIND 递归），收集 {path, mtime, size}，匹配扩展名
  2. 与 DB 中该 source 的已有记录 diff：
     - 新文件 / mtime 或 size 变化 → 入待解析队列
     - 消失的文件 → 标记 deleted（物理删除放在确认后，防误删歌单）
  3. 并发解析（rayon，IO 密集，线程数 = min(8, cpu)）：
     lofty 读 tag → symphonia/文件头读时长与码率
  4. 批量入库（事务，每 500 条 commit 一次）
  5. emit('scan:progress', {done, total, current}) → 前端进度条
  6. 重建 FTS 增量、归一化 albums/artists、补齐封面缓存
```

- 10 万级库首扫预期 2~5 分钟（SSD），扫描可中断、可后台；期间前端可正常浏览已入库部分。
- P1：notify 监听本地目录，防抖 2s 后增量扫描变化的子树。

### 4.3 封面与缓存

- 内嵌封面：首次按专辑取一首的封面，用 `image` crate 降采样到 512px JPEG，存 `{app_data}/covers/{album_hash}.jpg`；列表缩略图再降采样 64px 生成。
- 外部约定：同目录 `cover.jpg / folder.jpg / front.png` 优先级低于内嵌。
- 缓存上限：默认 500MB，LRU 清理；设置页可调整。

## 5. 局域网子系统设计（核心差异化）

### 5.1 三类远程源，一张统一抽象

```
                    ┌──────────── RemoteSource trait ────────────┐
                    │  list_dir(path) -> Vec<Entry>              │
                    │  stream_url(track) -> 内部流标识             │
                    │  credentials()                              │
                    └──────┬──────────┬──────────────┬───────────┘
                           │          │              │

                  (对方跑本应用)     (NAS 标准)
```

### 5.2 共享模式（F12，服务端）

- 设置页开关「在局域网共享我的音乐库」，打开后：
  - axum 监听 `0.0.0.0:45678`（可配置）；
  - mdns-sd 广播服务 `_lanmusic._tcp.local`，TXT 记录：`{app_ver, lib_name, device_name, token_hint}`。
- 接口（均为 JSON + 流式二进制）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/hello` | 握手，返回库名、歌曲数、协议版本 |
| `GET /api/tracks?offset=&limit=` | 分页元数据 |
| `GET /api/browse?path=` | 按目录浏览 |
| `GET /api/stream/:track_id` | 音频流，支持 Range |
| `GET /api/cover/:album_id` | 封面图 |
| `GET /api/lrc/:track_id` | 歌词 |

- **鉴权**：首次配对时对方出示 6 位 PIN，输入后交换 token；token 存双方本地。所有请求带 `Authorization: Bearer`。默认只读、只允许 LAN 网段（拒绝非私有地址段来源）。
- 隐私边界：共享的是**你选择共享的 source**（可选部分目录），默认全库但显式提醒。

### 5.3 WebDAV 源（F13）

- 表单填 URL/账号/密码（密码用 DPAPI/Keychain 加密存储，走 tauri-plugin-stronghold 或系统钥匙串封装）。
- 实现：reqwest 手写 PROPFIND（Depth:1）解析 XML 列目录，`GET` + Range 拉流。不引入重型 WebDAV SDK。
- 扫描策略：懒式——先按目录树浏览按需入库，或「扫描整个源」后台跑（同一套 scan pipeline）。

### 5.4 发现与连接体验


## 8. 安全设计

1. **CSP**：`default-src 'self'`，禁 `unsafe-eval`；img 允许 `asset:` 与 `music:` 协议。
2. **自定义协议白名单**：`music://` 只接受内部 track_id 解析，不接受任意文件路径；路径穿越校验。
3. **局域网共享**：默认关闭；绑定私有网段校验；token 鉴权；接口只读；日志可查。
4. **凭证存储**：WebDAV 密码存系统钥匙串（macOS Keychain / Windows Credential Manager / Linux Secret Service，已实现；钥匙串不可用时回退明文存库），不落 SQLite 明文。
5. **Tauri capability 最小化**：fs 权限只授予用户选择的目录与 app_data；远程源一律走 Rust 代理，前端不直连（避免 CORS 与凭证暴露）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| WebKitGTK（Linux）解码器不全 | Linux 格式支持弱 | 转码兜底作为一等公民；Linux 包声明依赖 GStreamer 插件 |

## 11. 附录

### A. `music://` Range 协议实现要点

```rust
// 伪代码
register_asynchronous_uri_scheme_protocol("music", |ctx, request, responder| {
    spawn(async move {
        let url = request.uri();                 // music://track/123
        let track = resolve(url)?;               // 查 DB 决定数据源
        let range = parse_range(request.headers());
        let (start, len) = compute(range, track.file_size);
        // 本地: tokio::fs::File seek + read
        // 远程: reqwest GET with Range header 透传
        responder.respond(Response::builder()
            .status(206)
            .header("Content-Range", format!("bytes {}-{}/{}", start, end, total))
            .header("Accept-Ranges", "bytes")
            .header("Content-Type", mime_of(track.format))
            .body(stream)…);
    });
});
```

- 必须正确返回 `Accept-Ranges: bytes` 与 206，否则 `<audio>` 无法 seek。
- 首包快速返回（立即给前 64KB 再继续流式），降低起播延迟。
- `Content-Type` 影响 WKWebView 解码器选择，须按真实容器填。

### B. 播放错误恢复策略

```
audio.error → 分类处理：
  文件不存在/权限   → track 标记 invalid，toast 提示，自动 next
  网络源超时       → 重试 1 次(指数退避) → 设备离线横幅 → next
  解码失败(WebView) → 请求 Rust 转码重试一次 → 仍失败则提示
```
