## 1. 产品概述

### 1.1 一句话定位

一款注重隐私、轻量快速的桌面音乐播放器：**本地音乐库管理 + WebDAV 远程库（NAS / 家庭服务器）**，无在线流媒体、无账号、无广告。

### 1.2 要解决的问题

- 主流播放器（QQ 音乐、Spotify 等）以在线内容为中心，对本地音乐库的管理越来越弱。
- 用户音乐文件分散在多台设备：PC、NAS、家庭服务器，缺乏一个轻量的方式在局域网内浏览和播放这些文件。
- 现有方案（foobar2000、MusicBee）功能强但 UI 老旧、配置复杂；NAS 自带应用体验差且被厂商锁定。

### 1.3 目标用户

1. **本地音乐收藏者**：手里有几百 GB～几 TB 的音乐文件（FLAC/MP3/APE），需要好的库管理和播放体验。
2. **NAS / 家庭网络用户**：音乐存在群晖/威联通/自建服务器上，希望在桌面端流畅播放。
3. **多设备家庭**：家里多台电脑都想访问同一份音乐，不想来回拷贝。

### 1.4 核心价值主张

- **纯本地**：所有数据（数据库、缓存、配置）都在本机，不联网上传任何信息。
- **跨源统一**：本地目录与远程 WebDAV 源在同一个库里浏览、搜索、排队、进歌单。
- **轻快**：Tauri 方案安装包 < 15 MB，内存占用 < 150 MB（对比 Electron 方案 150 MB+ 安装包）。
- **开放格式**：MP3 / FLAC / M4A / AAC / OGG / WAV / APE 等（播放取决于系统 WebView 解码能力，元数据入库全支持）。

### 1.5 竞品参考

| 产品 | 借鉴点 | 我们的差异 |
| --- | --- | --- |
| foobar2000 | 强大的库管理与格式支持 | UI 现代化、开箱即用、支持 WebDAV 远程源 |
| MusicBee | 视图丰富（专辑网格/表格）、自动打标签 | 跨平台、更轻 |
| Dopamine / 耳机 | 简洁美观、专注播放 | 增加 WebDAV 远程源，本地/远程统一体验 |
| NAS 自带 Audio Station | 局域网访问 NAS 音乐 | 桌面端、不锁厂商、跨平台、本地与远程同一库 |

## 2. 需求分析

### 2.1 核心用户故事

- 作为用户，我想**把几个文件夹加入音乐库**，应用自动扫描出所有歌曲并按专辑/艺人/风格组织。
- 作为用户，我想**双击一首歌就播放**，能看到封面、歌词、进度，能拖动进度条。
- 作为用户，我想**创建歌单**、拖拽歌曲排序，并把当前播放队列保存为歌单。
- 作为用户，我想**连接 NAS / 服务器的 WebDAV 音乐目录**，像本地文件一样浏览和播放。
- 作为用户，我想**搜索**：输入关键词即时过滤出歌名/艺人/专辑匹配的歌曲。
- 作为用户，我想**最小化到托盘**，通过托盘菜单或 Windows 任务栏缩略图按钮控制播放。

## 3. 总体架构

### 3.1 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        Tauri 应用进程                            │
│                                                                 │
│   ┌───────────────────── WebView（前端） ───────────────────┐    │
│   │ Vue 3 + Pinia · views / stores / components · i18n      │    │
│   │ <audio>/<img> → music:// cover://（自定义协议 URL）      │    │
│   └──────────────────────────┬─────────────────────────────┘    │
│                              │ IPC（invoke / event）            │
│   ┌──────────────────────────▼─────────────────────────────┐    │
│   │  Rust Core（src-tauri）                                 │    │
│   │  scanner · metadata · db · covers · lyrics · watcher    │    │
│   │  network(WebDAV) · scheme(流协议) · tray · thumbbar ·    │    │
│   │  updater · keyring · fonts · commands                    │    │
│   └──────────────────────────┬─────────────────────────────┘    │
│                              ▼                                  │
│   SQLite（rusqlite, WAL）  系统钥匙串  封面/歌词缓存目录           │
│                                                                 │
│   数据来源：本地文件夹（目录监听自动扫描）                        │
│              WebDAV（NAS / 服务器，浏览或整库扫描入库）           │
└─────────────────────────────────────────────────────────────────┘
```

前端不直接访问文件系统：本地与远程统一成 `music://` 流 URL（Rust 侧按 source 路由取流），封面/歌词同理走协议 URL，避免跨域与凭证暴露。

### 3.2 关键技术选型与理由

| 领域 | 选型 | 理由 / 备选 |
| --- | --- | --- |
| 应用框架 | **Tauri 2.x** | 包体小、内存低、Rust 生态成熟；备选 Electron（体积大，放弃） |
| 前端框架 | **Vue 3.5 + TypeScript + Vite** | 用户指定；组合式 API 适合播放器这类强状态应用 |
| 状态管理 | **Pinia** | 官方推荐，TS 友好 |
| UI | **TailwindCSS 4 + 自绘组件** | 播放器 UI 高度定制，组件库风格难匹配 |
| 虚拟列表 | **自研虚拟滚动（VirtualList）** | 10 万行歌曲表格必须虚拟化 |
| 元数据解析 | **lofty**（Rust） | 覆盖 ID3v1/v2、Vorbis、FLAC、MP4、APE，支持内嵌封面与歌词；备选 taglib（C++ 绑定重） |
| 音频解码 | **系统 WebView（WebView2 / WKWebView / WebKitGTK）** | `<audio>` 解码交给系统，Rust 只按 Range 取流（见 3.3），不自带解码器 |
| 数据库 | **rusqlite (bundled) + WAL** | 单文件、零部署；检索走 LIKE，不引入 FTS 虚拟表 |
| 远程源 | **reqwest（rustls）手写 PROPFIND** | WebDAV 列目录、Range 拉流，不引入重型 WebDAV SDK |
| 文件监听 | **notify** | 跨平台目录变化监听，触发增量扫描（3s 去抖） |
| 系统能力 | **tauri-plugin**（tray / single-instance / updater / process / dialog / shell 等） | 官方插件，免自研 |

### 3.3 播放引擎的关键决策 ⭐

**决策：播放采用「WebView `<audio>` + Rust 自定义流协议」。Rust 不携带解码器，只负责按 `Range` 取流并按来源路由。**

```
前端 <audio src="music://track/123">
          │
          ▼
Tauri register_asynchronous_uri_scheme_protocol("music")
          │  按 Range 请求流式响应（支持拖动进度条）
          ▼
Rust StreamResolver：
  ├─ track 在本地库  → 直接读文件流
  └─ track 在 WebDAV → reqwest 代理转发（统一附加凭证、解决跨域）
```

理由：

1. **解码交给系统**：WebView2（Windows）/ WKWebView（macOS）/ WebKitGTK（Linux）分别接入 Chromium、AVFoundation、GStreamer 媒体框架，覆盖主流格式，Rust 无需捆绑解码器。
2. **输出走系统混音器**：自动获得音量混合、蓝牙耳机、系统音效设置，无需处理音频设备枚举。
3. **Seek 免费**：实现 Range 协议后，`<audio>` 的拖动进度、缓冲管理全部复用浏览器成熟实现。
4. **统一源路由**：无论本地还是 WebDAV，前端拿到的都是 `music://` URL；来源差异、鉴权全部封装在 Rust 侧。

**系统解码能力说明**：

| 格式 | Windows(WebView2) | macOS(WKWebView) | Linux(WebKitGTK) |
| --- | --- | --- | --- |
| MP3 | ✅ | ✅ | ✅ |
| AAC / M4A | ✅ | ✅ | ✅ |
| FLAC | ✅ | ✅ | ✅ |
| WAV | ✅ | ✅ | ✅ |
| OGG / Opus | ✅ | ⚠️ 依系统版本 | ✅ |

> Linux WebKitGTK 的编解码器依赖发行版 GStreamer 插件，兼容性以系统为准；系统不支持的格式播放会提示并自动跳到下一首（无内置转码，属已知取舍）。

## 4. 数据设计

### 4.1 SQLite 数据模型（ER 概览）

```
sources ──1:N── tracks ──1:N── lrc_files（外挂歌词）
  │                  │
  │                  ├──N:M── artists（track_artists 关联表，支持合作曲目）
  │                  │
  │                  └──1:N── albums（title + artist_id 聚合，封面惰性缓存）
  │
  └── playlist_items（歌单条目，position + added_at）

最近播放与收藏：tracks.play_count / last_played_at / fav 字段
```

核心表 DDL（示意，完整定义与迁移见 `src-tauri/src/db.rs`）：

```sql
-- 音乐来源：本地目录 / WebDAV
CREATE TABLE sources (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,            -- 'local' | 'webdav'
  name TEXT NOT NULL,
  base_path TEXT,                -- 本地源根目录
  base_url TEXT,                 -- WebDAV 根 URL
  config TEXT,                   -- JSON：用户名 / 快速导入开关等（密码存系统钥匙串）
  enabled INTEGER DEFAULT 1,
  fast_import INTEGER DEFAULT 0,
  last_scan_at INTEGER
);

CREATE TABLE artists (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE COLLATE NOCASE
);

CREATE TABLE albums (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  artist_id INTEGER REFERENCES artists(id),
  year INTEGER,
  has_cover INTEGER DEFAULT 0,   -- 封面是否已缓存
  cover_url TEXT,                -- WebDAV 源封面远程 URL
  remote_id INTEGER
);

CREATE TABLE tracks (
  id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  path TEXT NOT NULL,            -- 相对 source 的路径（远程为 URL path）
  title TEXT NOT NULL,
  artist_id INTEGER, album_id INTEGER, genre TEXT,
  track_no INTEGER, disc_no INTEGER, year INTEGER,
  duration REAL, sample_rate INTEGER, channels INTEGER,
  bit_depth INTEGER, bitrate INTEGER, format TEXT,
  has_embedded_lyrics INTEGER DEFAULT 0,
  has_mv INTEGER DEFAULT 0,      -- 是否存在同名视频文件（MV）
  meta_state INTEGER DEFAULT 1,  -- 0=快速导入（仅文件名） 1=完整解析过标签
  fav INTEGER DEFAULT 0,
  mtime INTEGER, file_size INTEGER,
  added_at INTEGER, last_played_at INTEGER, play_count INTEGER DEFAULT 0,
  remote_id INTEGER,
  UNIQUE (source_id, path)
);
CREATE INDEX idx_tracks_album ON tracks(album_id);
CREATE INDEX idx_tracks_artist ON tracks(artist_id);

-- 曲目 ↔ 艺人多对多："A / B" 类合作曲拆成独立艺人，ord 记录展示顺序
CREATE TABLE track_artists (
  track_id INTEGER NOT NULL REFERENCES tracks(id) ON DELETE CASCADE,
  artist_id INTEGER NOT NULL REFERENCES artists(id),
  ord INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (track_id, artist_id)
);

CREATE TABLE playlists (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL,
  description TEXT, created_at INTEGER, sort INTEGER DEFAULT 0
);
CREATE TABLE playlist_items (
  id INTEGER PRIMARY KEY,
  playlist_id INTEGER NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  track_id INTEGER NOT NULL REFERENCES tracks(id) ON DELETE CASCADE,
  position INTEGER NOT NULL DEFAULT 0,
  added_at INTEGER               -- 加入时间（歌单内倒序展示）
);

-- 外挂歌词缓存：path 为本地 .lrc 文件路径或 WebDAV 完整 URL
CREATE TABLE lrc_files (
  track_id INTEGER PRIMARY KEY REFERENCES tracks(id) ON DELETE CASCADE,
  path TEXT
);

CREATE TABLE app_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

远程源（WebDAV）的歌同样进 `tracks` 表，用 `source_id` 区分——这样搜索、歌单、收藏对全库生效，播放时由流协议按 source 路由取流。

### 4.2 扫描算法（增量）

```
scan(source):
  1. 遍历：本地 walkdir / WebDAV PROPFIND 递归，收集 {path, mtime, size}，匹配扩展名
  2. 与 DB 中该 source 的已有记录 diff：
     - 新文件 / mtime 或 size 变化 → 入待解析队列
     - 消失的文件 → 从库中移除
  3. 并发解析（多线程共享任务队列）：lofty 读标签（标题/艺人/专辑/时长/码率等）
  4. 批量入库（事务，分批 commit），归一化 albums/artists（含 track_artists 关联）
  5. emit('scan:progress', {phase, done, total, current}) → 前端进度
  6. 补齐封面缓存，并顺带执行一次封面缓存容量清理
```

- 本地源默认**完整解析**；对网络目录可开「快速导入」（仅按文件名/目录结构入库，`meta_state=0`），之后随时可对单源执行「完整解析」补全标签。
- 本地目录由 notify 监听，文件变化（新增/修改/删除/重命名）去抖 3s 后自动增量扫描；WebDAV 源无法监听，需手动重扫。

### 4.3 封面与缓存

- 内嵌封面：首次按专辑取一首的封面，降采样缓存到 `{app_data}/covers/{album_hash}.jpg`；列表缩略图再降采样生成。
- 外部约定：同目录 `cover.jpg / folder.jpg / front.png` 优先级低于内嵌；WebDAV 源封面通过远程 URL 记录，经 Rust 拉取后落本地缓存。
- 缓存上限：默认 500MB（设置可调，`covers.max_mb`，0 = 不限制）；启动与扫描结束后清理，先清哨兵文件、再按修改时间从旧到新删封面。

## 5. WebDAV 远程源

远程源为唯一非本地来源类型，用于把 NAS / 家庭服务器 / 支持 WebDAV 的网盘音乐并入同一库。

- **添加**：设置页填 URL / 用户名 / 密码；密码存系统钥匙串（macOS Keychain / Windows 凭据管理器 / Linux Secret Service，不可用时回退明文存库），数据库仅保存用户名。
- **实现**：reqwest 手写 PROPFIND（Depth:1）解析 XML 列目录，`GET` + Range 拉流；不引入重型 WebDAV SDK。
- **使用方式**：可先按目录浏览试听；「扫描整个源」把目录树入库后，与本地歌曲一样参与搜索、歌单、风格视图与队列混排。
- **元数据**：远程曲目拉文件头（Range，1MB 上限）解析标签与时长；外挂 `.lrc` / 封面以完整 URL 记录，播放时经 Rust 代理获取。
- **断线处理**：拉流失败自动跳下一首并提示，应用不崩溃。

## 6. 前端设计

### 6.1 目录结构


### 6.2 播放器状态机

```ts
// stores/player.ts 核心状态
interface PlayerState {
  queue: Track[]            // 队列（快照）
  index: number
  status: 'stopped' | 'playing' | 'paused'
  mode: 'order' | 'loop' | 'one' | 'shuffle'
  position: number          // 由 <audio> timeupdate 节流更新
  duration: number
  rate: number              // 倍速，跨切歌延续
}
```

- 持久化：音量 / 倍速 / 模式 / 上次播放位置与来源（重开恢复「上次播到哪」）。
- `audio` 元素事件统一由 player store 收口：`ended → next()`，`error → 标记该 track 失效并 next()`，`waiting → UI 缓冲指示`。
- 播放控制入口：应用内快捷键（空格 / `N` / `P` / `Ctrl+F` / `[` / `]`）、托盘悬浮菜单、Windows 任务栏缩略图按钮。

### 6.3 页面与布局

- **侧栏**：全部歌曲 / 专辑 / 艺人 / 风格 / 音乐来源（本地与 WebDAV 源列表）/ 歌单，可折叠；底部入口进设置。
- **顶栏**：搜索框（全局过滤当前库）、当前视图标题、主题/皮肤入口、窗口控制。
- **主内容**：随路由切换列表、网格或歌单详情。
- **播放条（底部常驻）**：封面 / 曲名 / 进度 / 控制 / 音量 / 倍速 / 队列入口；随播放页上下文自适应配色。
- **播放页**：点击封面或曲目展开为全屏播放视图（大封面 + 时间轴歌词 + 队列面板）；播放中鼠标无操作自动隐藏顶栏与播放条（专注模式）。
- **独立窗口**：托盘悬浮菜单、桌面歌词浮窗（跟随主窗口播放状态）。
- **主题**：深 / 浅 / 跟随系统；播放页支持自定义皮肤（取封面主色 / 渐变背景）。

### 6.4 交互细节约定

- 双击行 = 立即播放并替换队列；单击行 = 选中；`Space` 全局播放暂停；`Ctrl+F` 聚焦搜索。
- 拖拽：文件管理器拖文件/文件夹到窗口 = 快速导入（临时 source）；歌单内拖拽排序。
- 列表多选 + 批量操作（加入歌单 / 队列）。
- 右键菜单：播放 / 加入队列 / 加入歌单 / 查看专辑 / 在文件管理器中显示（本地）/ 复制链接（远程）。

**Events（Rust → 前端）**

| 事件 | 载荷 | 触发 |
| --- | --- | --- |
| `scan:progress` | {source_id, phase: enumerate\|parse, done, total, current} | 扫描中持续 |

## 8. 安全设计

1. **CSP**：`default-src 'self'`，禁 `unsafe-eval`；img/media 仅允许 `asset:` 与自定义协议。
2. **自定义协议白名单**：`music://` 只接受内部 track_id 解析，不接受任意文件路径；路径穿越校验。
3. **凭证存储**：WebDAV 密码存系统钥匙串（macOS Keychain / Windows 凭据管理器 / Linux Secret Service），不落 SQLite 明文；钥匙串不可用时回退明文存库并在 UI 提示。
4. **前端不直连远程**：远程目录/封面/歌词/音频一律经 Rust 代理拉取，前端只接触本机协议 URL（避免 CORS 与凭证暴露）。
5. **Tauri capability 最小化**：fs 权限只授予用户选择的目录与 app_data；仅开启用到的插件能力。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Linux WebKitGTK 解码器依赖 GStreamer 插件 | 个别格式在 Linux 不可播 | 界面提示 + 自动跳下一首；README 标注系统依赖 |
| WebView 音频缓冲/延迟策略不可控 | seek 后起播略慢 | 协议层保守缓冲，先回少量数据再继续流式 |
| 10 万+曲库扫描与查询性能 | 卡顿 | 分页/虚拟滚动/LIKE 索引/批量事务/增量扫描；扫描后台线程 |

## 10. 附录

### A. `music://` Range 协议实现要点

```rust
// 伪代码
register_asynchronous_uri_scheme_protocol("music", |ctx, request, responder| {
    spawn(async move {
        let url = request.uri();                 // music://track/123
        let track = resolve(url)?;               // 查 DB 决定数据源（本地/WebDAV）
        let range = parse_range(request.headers());
        let (start, len) = compute(range, track.file_size);
        // 本地: tokio::fs::File seek + read
        // WebDAV: reqwest GET with Range header 透传
        responder.respond(Response::builder()
            .status(206)
            .header("Content-Range", format!("bytes {}-{}/{}", start, end, total))
            .header("Accept-Ranges", "bytes")
            .header("Content-Type", mime_of(track.format))
            .body(stream)…);
    });
});
```

- 必须正确返回 `Accept-Ranges: bytes` 与 206，否则 `<audio>` 无法 seek；分块读取需限制单块大小防 OOM。
- 首包快速返回（先回 64KB 再继续流式），降低起播延迟。
- `Content-Type` 影响系统 WebView 解码器选择，须按真实容器填。

### B. 播放错误恢复策略

```
audio.error → 分类处理：
  文件不存在/权限   → track 标记 invalid，toast 提示，自动 next
  远程源超时/断线   → 重试 1 次(指数退避) → 自动 next，UI 顶部离线横幅
  解码失败(系统不支持) → 提示该格式不可播，自动 next
```
